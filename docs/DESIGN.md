# Design

Confirmed design direction:

- Elesis should read as her base Elsword version, not a Grand Chase variant.
- The combat-animation model is an explicit asset-availability exception: it uses the supplied TDA Empire Sword rig for the Godot skeletal pipeline and sword Strike, but does not change the confirmed base-Elesis gameplay identity. The project operator confirmed redistribution permission for the converted runtime model on 2026-07-27.
- Avoid advanced Elsword class-path details such as Grand Master, Blazing Heart, Bloody Queen, Empire Sword, or Flame Lord.
- Visual style should follow `docs/design/ART_DIRECTION.md`: modern clean anime game-art, crisp cel-shading, visible dark outlines, readable silhouettes, moderate controlled detail, controlled crimson as the dominant color, black support tones, light readable silver metal, and restrained warm-gold accents. Avoid excessive gloss, heavy texture, rough painterly rendering, or dense splash-art detail unless the operator explicitly redirects the art style.
- Gameplay identity should start from sword-focused offense with restrained fire motifs, not from full evolution-class spectacle.
- The current mechanical identity is Counter Attack: Elesis prepares a visible counter power, then returns fixed, blockable, unpowered damage once per enemy attack hit received.
- Elesis' primary color is `#A32638`; the character model and card-pool accent color use this value.
- Card portraits currently use placeholder art while the Counter Attack pool is rebuilt.
- Character selection uses a separated background and Elesis character layer. The active default placement uses the `Soft 02` background at `0,0` scale `1.0`, with the active Elesis layer at `817,-54` scale `1.59`. The current background avoids the Belder/Velder fortress backdrop and instead uses a mostly unified crimson/dark field with abstract sword shapes so the background and Elesis can be positioned independently from the description text. The active character-select layer uses the cleaned pose 1 from `Elesis/images/versions/character-select/separated-v3/poses/`; earlier chroma-key and checkerboard attempts were rejected because transparent character assets must not keep visible colored fringes.
- The starter relic visual is the Belder Knight Emblem: a red-and-gold knight crest with a claymore motif on a transparent background, matching her red knight identity.
- Energy UI uses a red crystal-and-gold knight orb. Counter Attack should use a red-gold sword crest power icon until a dedicated icon is selected.
- Map marker art in solo and multiplayer reuses Elesis' compendium icon so her map presence matches the character icon.
- Combat, shop, and rest-site character art use official Elesis portraits when a matching official image exists, with transparent sprite assets and bottom-aligned scene placement. Each scene context owns its scale/offset tuning so the selected form stays close to the size of other STS2 character visuals while preserving the source portrait aspect ratio; combat, shop, and rest-site use the current specialization portrait. Large official portraits are imported with mipmaps and rendered with linear mipmap filtering so heavy in-game downscaling stays readable.
- Rest-site art uses the same official form portrait rule when available; runtime rest-site sprites render at 40% of their scene-authored scale so they do not cover the campfire choices. If a future form lacks official art, any fallback rest-site asset should be scaled to the same context size before being promoted.
- Specialization and base-form art lives under `Elesis/images/specializations/` as transparent sprites copied from the official Elwiki portrait references when available. Base Elesis uses `base/`; specialization art is grouped by path and numbered step, such as `saber_knight_path/1_saber_knight/`, `saber_knight_path/2_grand_master/`, and `saber_knight_path/3_empire_sword/`. Scene contexts that vary by form use the same path/step folder structure, for example `Elesis/scenes/rest_site/specializations/saber_knight_path/1_saber_knight/`.
- Specialization and evolution events use transparent official form portraits from `Elesis/images/specializations/` when they exist, so in-event previews match combat, shop, and rest-site specialization art; the initial specialization choice uses the existing base Elesis portrait. The specialization choice starts with base Elesis on the left and does not show the four specialization preview images above the option list. Choosing a specialization first previews that specialization portrait on the left and replaces the four choices with confirm/cancel buttons; confirm applies the specialization, while cancel returns to the four choices and the base Elesis portrait. Event portraits preserve their source aspect ratio, render at 70% of the default event portrait scale on both the initial and preview states, and are positioned one twelfth of the current viewport width to the left of the event portrait origin.
- The full 88-card pool uses its dedicated generated portrait pass. Attack, Skill, and Power art follow the separate red, blue, and plum/gold visual languages in `docs/design/ART_DIRECTION.md`, and the pool deliberately mixes character action with weapons, armor, objects, enemies, environments, effects, and emblems.
- Compendium and run/top-panel icon art uses the restored pre-v0.4.17 Elesis icon.

Do not treat generated art attempts as final until one is explicitly selected as the project asset.
